# MCP endpoint (`/mcp`): подключение личного плагина ChatGPT

Спецификация: `docs/tasks/mcp-endpoint-spec.md`. Реализация: `src/agent_manager/api/mcp/`
(генератор инструментов из OpenAPI, ASGI-роутер и in-process исполнитель через
`httpx.ASGITransport`). Тесты приёмки: `tests/test_mcp.py`.

## Что это

- MCP-сервер на транспорте Streamable HTTP, смонтированный в основное
  FastAPI-приложение на `POST /mcp` и `GET /mcp` (SSE).
- Инструменты генерируются автоматически из `app.openapi()` при старте
  приложения: любой новый роут появляется как MCP-инструмент после рестарта
  без ручных обёрток.
- Авторизация — существующий `Authorization: Bearer <token>` на каждом
  HTTP-запросе, включая запросы установленной MCP-сессии. Токен не попадает
  в аргументы, схемы и результаты инструментов: внутренние вызовы API
  выполняются in-process с заголовком вызывающего.
- RBAC, scoped-токены и OAuth в MVP нет: валидный административный токен даёт
  полный доступ. Execution-токены песочниц к `/mcp` не допускаются (403) —
  для `/mcp` нет правила в реестре permissions.

## Подключение в ChatGPT

1. Опубликуйте API за HTTPS (Traefik / Nginx / Cloudflare Tunnel), проксируя
   на `127.0.0.1:18767`:
   - не буферизуйте SSE-ответы — сервер сам ставит `X-Accel-Buffering: no`
     и `Cache-Control: no-cache`;
   - сохраняйте заголовок `Authorization` и chunked transfer encoding.
2. На [developers.openai.com/plugins](https://developers.openai.com/plugins)
   добавьте MCP-сервер:
   - URL: `https://<ваш-домен>/mcp`
   - аутентификация: Bearer token — текущий токен из `AGENT_MANAGER_API_TOKENS`.
3. После подключения попросите ChatGPT перечислить инструменты или начните
   новый чат: клиент читает реестр инструментов при подключении.

## После деплоя

- Рестарт сервера обновляет серверный реестр инструментов.
- Клиентский кэш ChatGPT сам не сбрасывается: обновите соединение плагина
  или начните новый чат.

## Проверка на изолированных тестовых данных

- Чтение: «покажи список задач» — инструмент `list_tasks_tasks_get`
  возвращает структурированный JSON.
- Запись: создайте тестовую задачу — ответ содержит `id` и подсказку с
  точным инструментом и аргументами для проверки результата.
- Долгая операция (`/ask`): диалог создаётся сразу, ответ секретаря может
  быть не готов. Инструмент по умолчанию не ждёт ответа (короткое ожидание
  ~1 с); `status: timeout` — это НЕ ошибка создания: инструмент вернёт
  `conversation_id` и состояние ожидания; проверяйте ответ чтением
  сообщений диалога. Повторно создавать диалог нельзя; чтобы подождать ответ
  в том же вызове, передайте `body.timeout_seconds` явно.
- Ошибки: 404 / 409 / 422 приходят как `isError=true` с HTTP-кодом и телом
  ответа API; изменяющие вызовы при таймауте автоматически не повторяются.

## Конфигурация и ограничения MVP

- Таймаут вызова инструмента: переменная окружения
  `AGENT_MANAGER_MCP_TOOL_TIMEOUT` (секунды, по умолчанию 55).
- Экспортируются только JSON-эндпоинты: multipart-загрузка вложений
  (`POST /tasks/{task_id}/attachments`) инструментом не является — бинарный
  файл через JSON-аргументы не передать.
- Аргументы инструментов сгруппированы: `path`, `query`, `body` — одноимённые
  параметры из разных источников не конфликтуют.
