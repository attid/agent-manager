# Telegram Secretary Interface MVP

Локальный Telegram-бот интерфейс к системе управления агентами и задачами (Agent Manager). Реализован на базе `aiogram 3` в строгом соответствии с [`telegram_secretary_mvp_tz.md`](file:///home/itolstov/Projects/mtl/AgentManager/telegram_secretary_mvp_tz.md).

## Архитектура

1. **Взаимодействие строго через HTTP API:**
   Бот не обращается напрямую к рабочей базе `tasks.db`, а взаимодействует с backend через `BackendClient` (`FastAPI`):
   - Управление задачами: `POST /tasks`, `GET /tasks`, `GET /tasks/counts`, `PATCH /tasks/{id}`.
   - Диалог и ходы: `POST /conversations`, `POST /conversations/{id}/messages`, `POST /conversations/{id}/turns`, `GET /turns/{id}`.
2. **Изолированное хранилище состояния бота (`UserStateStorage`):**
   - SQLite база данных с WAL-журналированием (`telegram_state.db`).
   - Хранит активный режим пользователя (`idle`, `new_task`, `talk`, `task`), привязку к задаче и сессии секретаря.
   - Хранит персистентную FIFO-очередь входящих сообщений. Переживает рестарт процесса бота без потери данных.
3. **Последовательная FIFO-очередь с отменой (`QueueProcessor`):**
   - Для одного диалога с секретарём одновременно обрабатывается строго одно сообщение.
   - При поступлении нового сообщения во время обработки другого отправляется статус: *"⏳ Сообщение в очереди на обработку"* с инлайн-кнопкой *"❌ Отменить"*.
   - Отмена возможна только до фактического старта обработки хода.
   - При освобождении диалога следующее сообщение автоматически извлекается из очереди, статус редактируется на *"⏳ Обрабатываю запрос..."* и запускается выполнение. Исходный контекст задачи/диалога сохраняется неизменным на момент отправки.
4. **Голосовые сообщения и скриншоты:**
   - Голосовые сообщения (.ogg) сохраняются в локальное медиа-хранилище и транскрибируются через Deepgram REST API (`nova-2`). Секретарю передаётся распознанный текст.
   - Скриншоты и фотографии сохраняются локально, ссылка на файл прикрепляется к метаданным сообщения. Вложение привязывается к конкретной паре «разговор + ход»; дочерняя сессия видит только текущий ход в `/inbox`, а прежние вложения того же разговора — только для чтения в `/attachments` и не считаются текущими.
5. **Авторизация:**
   - Middleware `AuthMiddleware` разрешает команды и сообщения только пользователю с `TELEGRAM_ALLOWED_USER_ID`. Всем остальным возвращается отказ: *"⛔️ Доступ запрещен"*.

## Режимы и команды

- `/start` — отображение статуса и стартового меню. В режиме `idle` сообщения не создают случайных задач.
- `/new` — переход в режим постановки новой задачи. Первое отправленное сообщение создаёт черновик карточки (`status="incoming"`) и связывает сессию секретаря.
- `/talk` — переход в режим общего диалога с секретарём (обсуждение проектов, статусов).
- `/list` — просмотр задач по категориям (*«Новые»*, *«Работа»*, *«Ошибки»*, *«Вопросы»*, *«Готово»*, *«Архив»*). На кнопках категорий, кроме архива, показано актуальное количество задач.
- Выбор карточки задачи: отображает описание, текущий статус и кнопки быстрых действий:
  - *«📥 Во входящие»*
  - *«⚙️ В работу»*
  - *«💬 Обсудить с секретарём»* (привязывает контекст активного диалога к задаче)
  - *«📋 К списку задач»*

## Переменные окружения

```bash
TELEGRAM_BOT_TOKEN="123456789:ABCdef..."       # Токен от @BotFather
TELEGRAM_ALLOWED_USER_ID=12345678              # Ваш Telegram User ID
AGENT_MANAGER_BACKEND_URL="http://127.0.0.1:8000"  # URL бэкенда FastAPI
DEEPGRAM_API_KEY="your-deepgram-api-key"       # API-ключ Deepgram (опционально)
TELEGRAM_STATE_DB_PATH="~/.local/share/agent-manager/telegram_state.db"  # База состояния бота
TELEGRAM_MEDIA_DIR="~/.local/share/agent-manager/telegram_media"         # Каталог для загрузок
```

## Запуск бота

```bash
PYTHONPATH=src .venv/bin/python -m agent_manager.telegram
```
