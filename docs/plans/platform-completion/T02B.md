# T02B — Stable authentication mode and internal client wiring

Base: 74ed17e in the T02 worktree. This is a narrow coordinator-confirmed follow-up, not a new architecture exercise.

Confirmed defect: BearerAuthMiddleware open mode depends on permissions.enabled (current grant count). With no configured administrative token, issuing the first grant switches a formerly anonymous service to protected mode, breaking an unconfigured Telegram/backend client. Revoking the last grant reopens anonymous access. Authorization must be a stable per-instance decision, never depend on current grant count.

Implement and test a stable explicit auth mode: production/unified service with execution permissions is protected from startup through revocation; administrative/internal Telegram HTTP calls have a valid host-only administrative principal; a child always gets only its execution grant. Existing standalone test/API open mode can remain only when explicitly using no security registry/admin configuration. Do not change behavior merely by the first execution. No administrative token in child configs or logs. Do not create a secret side file as a workaround; ephemeral host internal token can be held in the service instance, with caller-supplied admin credentials supported.

Mandatory tests: (1) before any grant protected API denies anonymous mutation; (2) after issuing and revoking last grant anonymous mutation is still denied; (3) actual service-created Telegram BackendClient/internal HTTP credentials work before and during secretary execution, while the child credential cannot gain admin access; (4) existing explicit open development mode remains a deliberate documented choice. Also check issuer tokens are revoked when executions finish; no reopening on revoke.

Scope: middleware/auth registry, service setup/client configuration and targeted tests. Preserve the T02 implementation. Do not touch T01 operation code. Read only relevant functions listed above after Codespaces scoping. Run focused tests without output pipelines, commit, and write T02B-result.md. Update stale T02 implementation SHA in its report if needed; preserve original evidence. No full suite, nested delegation, push, prod, or real LLM calls.
